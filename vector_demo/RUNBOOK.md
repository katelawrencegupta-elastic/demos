## Talk-track notes per segment
### Serverless vs ECH (no live ECH; use a table)
- Serverless: no nodes/shards/versions to manage, compute/storage decoupled (Search AI Lake), usage-based, always current (this project is 9.7.0).
- ECH: you choose hardware profile, tiers, ILM, version timing; some features/settings are not exposed on serverless. Verify the current gap list in the docs before presenting.
- On this project: `GET /` shows `build_flavor: serverless`; no `_cluster` node tuning; EIS endpoints are present out of the box.

### EIS + large embeddings
- EIS = Elastic Inference Service: GPU-hosted models, no ML nodes to size. Endpoints are prefixed with a dot (`.jina-embeddings-v5-text-small`, `.elser-2-elastic`, `.openai-text-embedding-3-large`...). `semantic_text` = zero-config inference at ingest AND query time, with automatic chunking.
- Long product descriptions (250-350 words) are chunked (sentence strategy, 250 words max, 1 sentence overlap) so no truncation at model context limits.
- **Honest numbers for this demo:** Elastic keeps the original float vectors for rescoring, so quantized formats add a small copy on disk and cut memory sharply. Serverless exposes no reliable store-size API (`_cat/indices` store.size is node-local and swings between 0b and KB/MB; `_stats`, `_cat/shards`, `_disk_usage` are unavailable), so do not show it live. Use the calculated footprint (walkthrough step 5) and the scale math:
  - 10M vectors x 3072 dims x 4 B = ~123 GB float32 HNSW RAM; int8 = ~31 GB; BBQ (1 bit + corrections) = ~4 GB. ~32x less vector data to hold in memory.
  - Levers to mention: BBQ + oversampled rescoring, Matryoshka/truncated dims (Jina v5, OpenAI 3-large `dimensions`), smaller model (Jina v5 nano/small), sparse ELSER (no dense memory cost).
- Agreement: on 24 test queries over 1,254 products, BBQ matched float's top result 24/24 and top-10 overlap was 99% (int8 98%). That is agreement on test queries, not a recall benchmark.

### GenAI / RAG / transparency
- Same API for every model: swap `inference_id` (Claude, Gemini, GPT, gpt-oss, Nemotron, Kimi, Qwen, GLM all listed by `GET _inference`).
- Transparency: `GET _inference/_all` is the inventory; `converse` returns `model_usage` (connector_id, model, input/output/cached/reasoning tokens, llm_calls), the tool-call `steps`, and a `trace_id`.
- Default Agent Builder agent currently runs `.anthropic-claude-5.5-opus-chat_completion`.

### MCP + A2A (Agent Builder, Kibana)
- MCP: `POST $KB_URL/api/agent_builder/mcp` (needs `Accept: application/json, text/event-stream`). 25 tools exposed, including your `demo_search_products` and `demo_search_docs`, ES|QL, index explorer.
- A2A: agent card at `/api/agent_builder/a2a/elastic-ai-agent.json`; `message/send` JSON-RPC at `/api/agent_builder/a2a/elastic-ai-agent`.
