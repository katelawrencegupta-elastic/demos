    Lab 4 · 20 min

    Governance blueprint

    This is the session. Labs 1–3 were evidence. Leave with named deliverables.

    Lab 4

    Operating model, not a feature matrix

    Fleet-managed

    Central policy, health, versions. Use where central governance is required.

    Day one: Fleet policies + integration allow-list, owned by platform.

    EDOT-native / standalone

    Full collector flexibility. Config lifecycle is now the team’s problem.

    Day one: version, approve, promote, audit — or it is a snowflake.

    Do not re-open SRE-01

    EDOT SDKs → Managed OTLP / Agent Gateway, not APM Server OTLP. Architects decide who is allowed which path.
