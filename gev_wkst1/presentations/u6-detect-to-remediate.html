    Setup trap

    Declaring triggers: type: alert on the YAML is not enough. The rule must list system-connector-.workflows with workflowId: elasticco-detect-remediate, and the workflow must be enabled.

    Enrichelasticsearch.esql.query

    Three queries before the agent talks

    Workflows pulls the same evidence the RCA agent’s tools use — so the prompt is grounded even before tool calls.

    query_oom K8s

    OOMKilled, BackOff, max restart.count — last 60 minutes.

    FROM logs-elasticco.k8s.event-default,
     metrics-elasticco.k8s.pod-default
| STATS oom, backoff, max_restarts
    query_slow_db APM

    PostgreSQL spans >2s for acme-retail — FOR UPDATE.

    FROM traces-apm-default
| WHERE span.subtype == "postgresql"
  AND tenant.id == "acme-retail"
| STATS n, p95_ms, max_ms
    query_tenant_p95 blast

    checkout-api error rate and p95 by tenant.id.

    FROM traces-apm-default
| WHERE service.name == "checkout-api"
| STATS … BY tenant.id
| EVAL error_rate_pct, p95_ms
    Why enrich in the workflow

    Elasticsearch stays the source of truth. The agent still calls its tools; the workflow just does not start from an empty prompt.

    Reasonai.agent

    Agent Builder, same agent as U5

    Official Elastic RCA example uses elastic-ai-agent. This demo must use elasticco-rca-agent so the tools and rollback instruction stay planted-incident-specific.

    Three agent steps
    StepJob
    rca_analysisNew conversation. Alert + ES|QL results in the prompt.
    case_titleReuse conversation_id. Title only.
    case_descriptionSame conversation. Description only.
    What it must not do

    No kubectl. No src.cli incident. No invented p95. If tools are empty, say evidence is insufficient. Remediation is always: roll back checkout-api v2.4.1 → v2.4.0.

    Conversation

    create-conversation: true on the first call so title, description, and the reasoning comment share one Agent Builder thread.

    TrackRemediate

    Cases is the audit — rollback is a comment

    The workflow opens an Observability case, attaches the firing alert (when present), posts the agent analysis, then a human-in-the-loop remediation comment.

    Case steps
    cases.createCaseowner observability, severity high
    cases.addAlertsKQL if when an alert id is present (skip on manual Run)
    cases.addCommentagent message + reasoning trace
    add_remediationroll back to v2.4.0 — do not execute
